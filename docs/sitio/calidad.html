Pruebas automáticas

El proyecto es JavaScript, así que en lugar de JUnit (de Java) usa sus equivalentes: el runner nativo de Node (node:test) en el backend, Vitest en el frontend y Playwright para recorrer la app en un navegador real. Cada prueba usa una base temporal: nunca toca los datos reales.

Frontend (frontend/src/**/*.test.jsx, Vitest)

Cada pantalla y componente con Testing Library: el formulario por pasos de Agregar compra, la Lista de compras con casillas y páginas, el Catálogo, los usuarios, el aviso antes de perder datos, el Excel con su hoja Resumen y api.js en sus dos modos (servidor con fetch simulado, y local).

De punta a punta (frontend/e2e/, Playwright)

Un navegador real usa la app completa con su propio backend, en escritorio y en teléfono (Pixel 7): acceso, compras, artículos, casillas y páginas de la lista, Catálogo, usuarios, aviso de salida, navegación (ningún botón cortado de 1280 a 320 px) y vista móvil. Una prueba falla si la página lanza un error o el servidor responde 5xx.

Versión del cliente (desktop/pruebas/)

Abre el .cmd de la carpeta armada y comprueba que se abre, guarda, exporta, se apaga y conserva los datos.

Cómo correrlas

# backend/
npm test

# frontend/
npm run lint
npm run test:run
npm run test:e2e        # la primera vez: npx playwright install chromium
npm run build

# desktop/ (Windows)
npm run preparar
npm run test:escritorio

Antes de abrir un Pull Request se corren todas. Si el puerto 3100 o 5174 está ocupado, E2E_PUERTO_BACKEND y E2E_PUERTO_FRONTEND los cambian.

Seguridad

Cada control tiene su prueba: contraseñas con hash, bloqueo por intentos fallidos, sesión que vence, permisos en cada petición, validación de entradas, SQL con parámetros, errores sin detalles internos, exportar solo con permiso y respaldo antes de reemplazar la base. La tabla completa está en docs/SEGURIDAD.md.

Flujo de trabajo

  • Una rama por cambio y Pull Request hacia main, revisado por otro integrante.
  • Commits pequeños, en español, con prefijo y área: feat(compras): …, fix(agregar-compra): …, docs: …, test: ….
  • Revisiones con las skills del proyecto (.claude/skills/): marca, accesibilidad, frontend, backend, seguridad y auditoría completa (full-audit).
  • Reglas del código en CLAUDE.md y en el README.md de cada carpeta.
